Allocation Algorithms Compared

The four classic heap allocation strategies. Select each in the visualiser above to see how they differ in fragmentation behavior and search speed.

First Fit
Scans the free list from the beginning. Allocates the first block large enough. Stops searching immediately after finding a fit.
O(n) search · fast
Behavior: Concentrates small leftover fragments near the beginning of the heap. Later, searches must traverse many tiny free blocks before reaching usable space.
Best Fit
Scans the entire free list. Allocates the smallest block that is still large enough — minimizes wasted space.
O(n) always · min waste
Behavior: Leaves many tiny fragments — the "leftover" after fitting tightly is often too small for future use. Can actually worsen external fragmentation.
Next Fit
Like First Fit but continues from where the last allocation ended, wrapping around when it reaches the end.
O(n) · even distribution
Behavior: Distributes allocations more evenly across the heap. Avoids the clustering problem of First Fit. Generally similar or slightly worse fragmentation than First Fit in practice.
Worst Fit
Scans the full free list. Allocates the largest available block — leaves the biggest possible remainder.
O(n) always · large fragments
Behavior: Theory: large leftovers are more useful. Practice: degrades quickly and produces highest fragmentation. Rarely used in production allocators.

Heap Allocation Concepts

How real allocators like ptmalloc (glibc malloc), jemalloc, and tcmalloc work under the hood.

How malloc() works (glibc)

In glibc's ptmalloc, each allocated chunk has an 8-16 byte header storing the chunk size and status flags. The malloc() call first checks size-specific bins (fastbins for ≤128 bytes, smallbins, largebins, unsorted bin) for a freed block that fits. If none exists, it extends the heap via sbrk() or mmap(). The minimum allocable chunk is 32 bytes on 64-bit systems — every request is rounded up to a multiple of 16 bytes.

  • Fastbins: LIFO cache for small freed chunks (≤128 bytes) — near-zero overhead reuse
  • Smallbins: 62 size-specific doubly-linked lists, 16–1008 bytes in 8-byte steps
  • Largebins: Range-based bins for chunks over 1008 bytes
  • Unsorted bin: Newly freed chunks land here before being sorted

External vs internal fragmentation

External fragmentation: Enough total free memory exists, but no single contiguous block is large enough for the requested allocation. Classic result of many malloc/free cycles with varying sizes. Compaction eliminates it but requires moving data and updating all pointers — expensive and rarely done in general allocators.

Internal fragmentation: The allocated block is larger than requested. Sources: alignment padding (allocators round up to alignment boundaries), minimum chunk size (ptmalloc has a 32-byte minimum), and header overhead. A malloc(1) call in glibc allocates at least 32 bytes — 31 bytes are internal fragmentation.

Coalescing — merging free blocks

When free() is called, a good allocator checks whether adjacent blocks are also free and merges them — this is called coalescing. Without it, external fragmentation grows unboundedly: a series of 64-byte frees can leave 16 separate 64-byte blocks where a 256-byte malloc will fail even though enough space exists.

Immediate coalescing (done at free() time) is simple but can be expensive if the same block is freed and reallocated repeatedly. Deferred coalescing batches the merges. ptmalloc uses immediate coalescing for regular bins but deferred for fastbins.

Modern allocator improvements

  • jemalloc (Firefox, FreeBSD): Per-thread arenas eliminate lock contention. Size-class binning reduces fragmentation to under 5%.
  • tcmalloc (Google): Thread-local caches for small allocations (≤256KB) — no lock needed for most allocations. Used in Chrome, Go runtime.
  • mimalloc (Microsoft): Free lists per page, very fast for short-lived allocations. 2-3× faster than system malloc on some benchmarks.
  • Arenas: Allocate a large slab upfront, satisfy requests within it, free the whole arena at once — zero per-object free() overhead. Used for parser/compiler memory.

Heap Allocator – FAQ

What is a heap allocator?+
A heap allocator manages the dynamic memory region (the heap) in a process. When you call malloc() in C or new in C++, the allocator finds a free block, marks it allocated, and returns a pointer. When you call free(), it marks the block available. The allocator tracks free and allocated blocks using data structures like free lists, bitmaps, or segregated size classes. Real-world allocators (ptmalloc, jemalloc, tcmalloc) add threading support, caching, and fragmentation reduction on top of these basic algorithms.
What is the difference between First Fit, Best Fit, Next Fit, and Worst Fit?+
First Fit: scans from the start, picks the first block that fits — fast but creates fragmentation at heap start. Best Fit: scans everything, picks the smallest sufficient block — minimizes waste but creates many tiny unusable fragments. Next Fit: like First Fit but resumes from last allocation position — more even distribution. Worst Fit: picks the largest block — leaves large remainders in theory, but in practice causes the worst fragmentation. Try each in the visualiser above with the "Fragmented" scenario to see the difference. First Fit generally performs best in practice — it's what glibc's malloc uses as a fallback.
What is memory fragmentation?+
External fragmentation: enough total free memory exists, but it's split into small non-contiguous blocks — a malloc(256) can fail even with 1KB free if no single 256-byte block exists. Internal fragmentation: the allocated block is larger than requested, wasting space inside the allocation — caused by alignment requirements and minimum chunk sizes. The "Checkerboard" scenario in the visualiser above creates maximum external fragmentation by allocating then freeing every other block. Load it then try a large malloc to see it fail despite plentiful free memory.
What is coalescing and why does it matter?+
Coalescing is merging adjacent free blocks into a single larger block when free() is called. Without coalescing, a heap that's been through many malloc/free cycles of similar-sized allocations will accumulate many small free blocks. Calling malloc() for a slightly larger size will fail even though equivalent total space is available. Run the "Coalesce demo" scenario in the visualiser to see a case where adjacent frees are merged. Modern allocators like ptmalloc perform immediate coalescing for normal chunks — adjacent free blocks are merged immediately when free() is called.
